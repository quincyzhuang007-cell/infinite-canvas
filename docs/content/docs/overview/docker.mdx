# Docker Deployment

## Use the published image

```bash
git clone git@github.com:basketikun/infinite-canvas.git
cd infinite-canvas
docker compose up -d
```

Open `http://localhost:3000`.

## Build locally

```bash
docker compose -f docker-compose.local.yml up -d --build
```

## LAN collaboration

The source deployment in `docker-compose.local.yml` also starts a collaboration service. Room snapshots persist in the `canvas-collaboration` volume. Each sync message is limited to 32 MB and each media file to 500 MB; media is streamed to disk by the server.

For LAN access, set `CANVAS_COLLAB_ADVERTISE_HOST` to the Docker host's LAN IP. To share the host CLIProxy, mount its configuration file read-only into the `collaboration` container and point `CANVAS_COLLAB_CLIPROXY_CONFIG` at that path. With Docker Desktop, also set `CANVAS_COLLAB_CLIPROXY_URL` to a container-reachable address such as `http://host.docker.internal:8317`. The current collaboration image does not bundle the Canvas Agent launcher, so Docker mode does not yet offer host Codex Agent invites; run the collaboration service from source on the host to use that mode.

Regular invites keep each member's own local Agent; when the collaboration service runs natively, a separate host-Agent invite gives each member an independent Codex conversation. Image generation in a shared canvas is routed only through the host CLIProxy. Never commit the CLIProxy API key or a participant's Agent session credential, or include either in invite links.

## Documentation image

The documentation in `docs/` is a separate Next.js standalone application with server capabilities.

```bash
cd docs
docker compose up -d
```

To build it from the current source:

```bash
cd docs
docker compose -f docker-compose.local.yml up -d --build
```

The main application container only runs Next.js. Canvases, My Assets, generation history, and API keys are stored in the browser by default, while prompt repositories are fetched directly by the frontend. No persistent data volume is required for this data.

## Optional analytics

No analytics are enabled by default. A deployment can enable GA4, Baidu Analytics, or both at runtime:

| Variable | Description |
| --- | --- |
| `ANALYTICS_GA4_ID` | Google Analytics 4 measurement ID (`G-XXXX`) |
| `ANALYTICS_BAIDU_ID` | Baidu site ID, the hash after `hm.js?` |

```yaml
services:
  app:
    image: ghcr.io/basketikun/infinite-canvas:latest
    ports:
      - "3000:3000"
    environment:
      ANALYTICS_GA4_ID: G-XXXXXXXXXX
      ANALYTICS_BAIDU_ID: e8263761cc5c32f5f7a855b8203b965a
```

SPA route changes automatically report page views to enabled providers. Only configure analytics IDs on sites you control, and do not commit them to the repository.
